Editing the game

A guide for someone who has never used GitHub. It all happens in a web browser — nothing to install, and nothing you can permanently break.

The two addresses you need

The gamequiz-metro.com
The codegithub.com/SamuelKimaniSikuku/paris-metro-game

Step by step

  1. Make a GitHub account.

    Go to github.com/signup. It's free. Use the email address Samuel invited, or you won't see the invitation.

  2. Accept the invitation.

    GitHub emails you a green Accept invitation button — click it. If it never arrives, sign in and open the repository address below with /invitations on the end.

  3. Open the code and find your file.

    Open the repository address above. The table overleaf says what each file holds. Click a file name to read it.

  4. Click the pencil icon.

    It sits at the top right of the file you're reading. The text becomes editable, like a normal text box.

  5. Make your change.

    Type directly into the page. Nothing is saved yet — if you get lost, close the tab and nothing at all happens.

  6. Click the green “Commit changes…” button.

    Top right. A small box opens. Write one short line saying what you did — for example “Add Bel-Air to line 6” — leave Commit directly to the main branch selected, and click the green Commit changes inside the box.

    “Commit” is simply GitHub's word for “save, with a note about why”.

  7. Wait about a minute, then look at the site.

    Every commit publishes automatically. To watch it, click the Actions tab at the top of the repository: a yellow dot means it's building, a green tick means it's live. Then reload quiz-metro.com.

    Page looks unchanged? That's your browser's saved copy — pull down to refresh on a phone, or hold Shift and click reload on a computer.

Step 6 publishes straight to the live site. If you'd rather Samuel looked first, choose Create a new branch for this commit and start a pull request in that same box instead. Nothing goes live; he gets a page showing exactly what you changed, and clicks Merge when he's happy.

Which file holds what

FileWhat's in it
data.jsThe métro itself — lines, stations, landmarks. Most content changes are here.
index.htmlPage layout and all the styling: colours, sizes, spacing
app.jsThe quiz questions and the pass-the-phone game
live.jsThe multiplayer rooms
crossword.jsThe crossword
net.js, config.jsThe plumbing that connects players. Leave these alone unless you know why you're changing them.

Two things that will save you time

Wording appears twice. The game plays in English and French. Text that players read lives in the T block near the top of app.js, live.js and crossword.js — each has an en: section and an fr: section. Change both, or one language will drift.

The dist/ folder is built, not written. It's the whole game squeezed into a single file for playing offline. It gets regenerated, so hand edits there are silently thrown away.

Adding a station — the most common change

In data.js, find the STATIONS list and add a line shaped like its neighbours: the station name, then the lines that serve it.

"Ledru-Rollin": ["8"],
"Père Lachaise": ["2", "3"],

Keep the accents exactly as the real station writes them — the game strips them when checking, so Pere Lachaise is still marked correct.

If you break something

Nothing is ever lost — GitHub keeps every version of every file.

Click Commits above the file list to see the history. Open the commit that caused the trouble and press Revert. The site goes back to how it was, usually within a minute. So experiment freely: that safety net is the whole point.
